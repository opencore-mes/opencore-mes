The problem

Growth means downtime and a bigger server.

Every change a maintenance window; every new line a hardware purchase; the shift-start burst slows everything down.

Solution

Changed while it runs

  • An approved change is live at once: no deploy, no window.
  • Open screens redraw by themselves; nobody signs out.
  • The database upgrades itself when a release starts.
Solution

More servers, not a bigger one

  • Add servers behind a balancer; every screen stays live.
  • Read replicas take the reads, never showing stale data.
  • Any server can stop without losing anything.
