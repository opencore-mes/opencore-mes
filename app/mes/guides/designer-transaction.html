A transaction is a form people fill in, scan into or press a button for: inputs, checks that must hold, and steps that write records, all or nothing, through each object's own policies and rules. You design it here, inside a change; it reaches the plant only once the change is reviewed, approved and executed.

Its tabs

The tabs
The transaction's settings, by topic. A number on a tab counts what differs there from the live version; a new transaction counts everything.
The numbers
Differences from the published version on that tab. Changes lists them all, line by line.

Copilot

The copilot
An AI that drafts, checks and explains, working on the whole change as you. It never submits, reviews or approves. A live design shows no copilot: press Change it first.
Not set up
Shown when this installation has no AI configured: it says what is missing.
The conversation
What you asked, its answers, and each design tool it used (a tick when it worked, a cross when not). It is kept with the change: come back any time and it picks up there.
The box
Type what you want ("add a check that the machine is up"). Ctrl+Enter (⌘+Enter on a Mac) sends it. What you type is kept if you leave the tab.
Attach
Adds up to five files for it to read: pictures, PDFs, CSV files or Excel workbooks. You can also paste or drop one into the box; × takes one off.
Send
Saves your unsaved edits first, so it works on what you see, then sends. What it saves shows in every window at once.
New conversation
Deletes the conversation kept with this change, after asking. The draft stays as it is.

Changes

The count
How many differences from the published version: changed, added, removed. A new transaction says so; one that matches what is live says "Nothing differs".
By tab
Differences grouped by the tab where each is edited. Open … takes this window to that tab.
A difference
Click its line to fold or unfold it. Lines starting with + are the draft, lines with − the published version. A green edge is added, amber changed.

General

Name
Its fixed name, set when it was created. Its screen opens at /t/ and this name.
Label
What its button and its screen say, such as Move in.
Description
One line shown under the title: what it does.
Appears on
Pick an object to put a button for this transaction on its records; the record is filled in when the button is pressed. Only in the navigator: no button on records.
…while they are
Tick the states in which the button shows. None ticked: in every state.
…only when
A condition on the record (read as {"record": "field"}): the button shows only where it holds. None: always.
…filling in
The input the record goes into: a reference input to that object that is not filled in from another one.
Confirm first
Ticked, the person sees what will change and confirms before it runs (recommended). Off, it runs as soon as the button is pressed.
Electronic signature
Type the signature's meaning (Performed) to have the person sign as they confirm, recorded with the run. Empty it to sign nothing.
Verified by a second person
Shown once it is signed. Ticked, a second person signs in beside the one running it and verifies; both re-enter their passwords at every submit.
…their signature means
What the second person signs to, such as Verified.
…who may verify: departments
Tick the departments whose members may verify. The one running it never verifies their own.
…or roles
Roles on objects, written object.role (lot.supervisor): anyone holding one may verify too. A tag list: suggestions are the roles the objects declare.
Fill the window
No: the usual page. On request: its screen has a Maximize button that sets the navigator, top bar and tabs aside. Always at first: it opens maximized. Each device remembers the person's choice.
Input flow
How the form is filled from a keyboard or scanner: which input comes next and what moves on. Pick one drawn in the Flow designer (kind input); none goes from input to input with Enter, in the form's order.
Open its screen
Shown once it is published: opens the live version, not your draft.

Inputs

The inputs
What the person enters or scans, one row each. A row tinted green is new in this change, amber changed.
Input
Its name, read by checks and steps as {"input": "name"}. Fixed once added.
Label
What the form says beside it.
Type
Text, a number, a date, a yes/no, a list of values (enum), an image, a reference to a record (ref), or rows: a table the person fills in line by line. Changing it clears what no longer applies.
Required
Ticked, it must be filled in before the transaction runs. To make it required only sometimes, use Required when on the Layout tab.
Refers to
For a reference: the object whose record it names (a lot, a machine).
Values
For an enum: the values offered, as a tag list. Tick several values to let the person pick more than one.
Rows
For a table input: its columns as tags written name:type (string, integer, decimal, boolean or date; string when left out), and the least and most rows allowed.
Filled in from
Entered: the person types or scans it. Or a field of a record another input names (the lot's machine): it is shown, filled in, and not typed.
Remove
Takes the input out of the draft, after asking.
New input, Add
Type a name in lower case (letters, digits, _; such as good_qty) and press Add. It starts as text; set its type in its row.

Layout

The form
The inputs laid out as the form shows them, on a row of 12 columns; on a narrow screen each takes the whole row.
Its tabs
Click one to lay it out; + tab adds a tab.
The tab's head
With more than one tab: its label, move left or right, and Remove tab (its inputs go to the tray).
A section's head
Its label; can fold and folded at first; the arrows move it up or down; the drop-down moves it to another tab; Remove takes it off (its inputs go to the tray).
An input's card
Drag it to move it, within a section or to another. Click it to select it and set it below. A green edge is new in this change, amber changed.
Its buttons
The arrows move it earlier or later; − and + make it narrower or wider (each kind of control has a narrowest width).
Add section
Adds an empty section to the tab shown. Drop inputs into it.
Not on the form
Inputs not placed yet: drag one onto a section, or use place in…. Drag a card here to take it off.
The selected input
Its width, how it is drawn (a drop-down, radio list, scan field, stepper…), rows for a text box, help text under it and a placeholder while empty. Take it off the form sends it to the tray.
Shown, enabled, required when
Condition boxes over the form as it is filled and the person. Empty: always shown, always enabled, required only as the Inputs tab says. The server checks required when too.
Preview
The form as the draft draws it, its inputs disabled.

Checks

A check
What must hold before anything changes. Each is checked again, under lock, the moment it runs. A failing one refuses the run with its words.
Must hold
A condition box over the inputs, the records they name ({"lookup": "machine.state"}), the person, and counts of records, as they were before any step.
Otherwise, say
What the person reads when it does not hold: what is wrong, and what to do.
On the input
The input the message is shown under, or the whole form.
remove
Takes the check out, after asking.
Add check
Adds a check (the first input must not be empty) for you to change.

Steps

A step
Each writes one record through its object's state machine, policies, rules and audit trail, as the person running it. They run in order, all or nothing. The object's policies must grant the write "only through transactions" naming this one.
Earlier, Later
Move the step up or down the order.
remove
Takes the step out, after asking.
On the record in
A step that changes a record: the reference input naming it. (On a step that creates a record, this place is Creates a: the object it makes.)
then takes the action
A transition of that object (from which states, to which), or none to only set fields. (On a step that creates a record: How many, one, or one per row of a table input, its fields then reading the row as {"row": "field"}.)
Sets
The fields the step writes, each field = value.
A value
Written as JSON on one line: {"input": "machine"}, a number, "text", or an expression. Outlined red until it reads; applied as soon as it does.
× (Don't set it)
Stops setting that field.
+ set a field
Pick a field to set. One named like an input starts as that input.
Only when
A condition box: the step runs only where it holds. None: always.
A suite's step: its settings
A step an installed suite adds: each setting a value or an expression, (needed) where it must be given. One that cannot be undone runs last. If its suite is not installed, it says so, and the transaction cannot run until the suite is back.
Add step
Adds a step that changes the record a reference input names. Greyed until there is a reference input.
Add: …
One button per step kind the installed suites add.
Add a step that creates a record
Adds a step that makes a new record of an object.

Scenarios

Make one in the sandbox
Opens the sandbox on this transaction. A scenario is recorded there: records picked from live (or given), steps run as someone, and what each should give.
A scenario
Its name, its records, and its steps: what each does, as whom, and what it expects (it runs, or it is refused with a message; a record's state after).
passed, failed
Its last run by the fitness test. A failed one shows why below it. A new or changed transaction without a scenario, or with one that fails, cannot be submitted.
open in the sandbox
Opens the scenario in the sandbox to run it or change it.
remove
Takes the scenario out of the draft, after asking.

Callers

Groups
Tick the groups whose members may run it. Nobody may until named here.
Users
People named one by one: type part of a name and pick from the suggestions; × on a name removes it.
Services
Tick the services whose scripts may run it (with ctx.transactions.run), as their own service role. A signed transaction is a person's to run: no service is offered.

Callers still need, on each object a step writes, a role whose policy grants that write through this transaction.

Try it

Open its screen
Runs the published version as you, with your rights; its Check button shows what would change without changing anything. Your draft is not what runs. Before the change is executed there is nothing to open: see the form on the Layout tab, or try the draft in the sandbox.

Stewards

Departments
Tick the departments that approve every change to it. A change to its inputs or steps is also approved by the stewards of each object, field and transition its steps write.

JSON

The whole transaction
All of it as JSON, for integrators. Edit it here; nothing changes until you apply.
Apply JSON
Replaces the draft with it, checked like any other edit. Refused if it does not read, or if the name changes.

Everywhere in it

Condition boxes
A rule in words. Click it, or Edit (Add a condition while empty), to build it from rows: a field, an operator, a value, in groups (all of, any of, none of), or from a pattern. JSON shows the same as text; Try lets you type values and see whether it holds. Empty means what its box says (always, never).
A condition's problem
Said in red under the box: what does not read, or names something unknown.
Tag lists
Chosen values as chips; × removes one. Click into the box for suggestions, Enter or a click adds one, Add "…" adds a new value, Backspace in the empty box removes the last. Some take only values from the list.
JSON on one line
A value or expression as JSON, outlined red until it reads; applied as soon as it does.
Diff marks
Green: added in this change. Amber: changed. What was removed is listed on Changes.
Remove, and Undo
Remove always asks first; nothing live changes until the change executes. Undo (⌘+Z or Ctrl+Z, outside a text box) brings it back.
