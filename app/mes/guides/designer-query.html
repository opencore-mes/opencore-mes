A named query is one SELECT over the query views, with parameters by name (:family). It writes nothing and grants nothing: it runs as whoever it is for, and their policies decide which rows and fields they get. Once live, a plan's input screen can draw a drop-down from it. On a live design, or a change you may not edit, every control here is read only.

Its tabs

The tabs
General opens first. Click a tab to see its settings; the open one is highlighted.
A number on a tab
How many things on that tab differ from the live version. On Changes, the total.
Remove, and Undo
Every Remove asks first. What is removed leaves this change only; nothing live changes until the change executes, and Undo (⌘Z or Ctrl+Z) brings it back.

Copilot

The conversation
Ask the AI to write, check or explain the query. It works as you, saves into this draft, and never submits. The conversation is kept with the change: it picks up here any time.
Ask the copilot…
Type what you want. ⌘ Enter or Ctrl+Enter sends; you can paste or drop a file into the box.
Attach
Adds a picture, a PDF, a CSV file or an Excel workbook (up to 5); × on a file takes it off.
Send
Saves your unsaved edits first, then sends. Greyed out while it works, or when no AI is set up.
New conversation
Asks first, then deletes the conversation kept with this change. The draft stays as it is.

Changes

The differences
What this change does to the query against the live version, grouped by tab: how many changed, were added and removed. Reviewers and approvers see the same.
Open …
Jumps to the tab where that group is edited.
A difference
Marked new, changed or removed; click it to open or close it. Lines marked − are the live version's, lines marked + the draft's.

General

Name
Fixed once created: a plan's field names the query by it.
Label
A text field: what designers pick it by.
Description
A text box: what it answers, and for whom.
At most (rows)
1 to 1000; 200 when empty. A list fed by the query never shows more.

Query

The SELECT
One SELECT (or WITH … SELECT), one statement, over the query views: one view per object, its columns the object's fields (the schema explorer on the Query page lists them). Write a parameter as :name; never paste a value into the text.
Its marks
A syntax error is marked on its line and said below; click the message to go there.
Parameters it uses
Each :name found in the text.
Not declared yet
In red: parameters the text uses that the Parameters tab does not declare. The query cannot be submitted until they are.
Declare them as text
Declares each as a text parameter, labelled from its name; change its type on Parameters.

Parameters

The parameters
One row for each :name the SELECT uses. A value given is checked against its type and bound as a parameter. Parameters are added from the Query tab, as the SELECT names them; one declared that the SELECT never uses is a problem to fix.
Rows marked
A parameter new in this change is shaded green; one changed, amber.
Type
A drop-down: text, whole number, number, yes or no, or date.
Label
A text field: the parameter in words, shown where values are typed.
Required
Tick it when the query must not run without this value: a required one missing runs nothing.
Remove
Takes the parameter out, after asking. If the SELECT still uses it, the Query tab says so.

Try and tests

Its parameters' values
One field per parameter: a date, a number or text, as its type says, with required ones marked.
Run it
Runs this draft as you. What you may read is what you see; a plan's drop-down shows each person what they may read.
Its error
In red, when it could not run: what the database or a check said.
The rows
How many rows, in how long, and its columns; the first 50 are shown.
Keep these values as a test
Keeps the values typed as a test, named after them.
Tests
The fitness test runs each as whoever submits the change: it must run, and give the columns the lists drawn from it name. Remove takes one out, after asking.

Stewards

Departments
Tick each department that approves every change to it. At least one is needed. A query writes nothing and grants nothing: it reads as whoever it runs for.

JSON

The query as JSON
All of it as data: its SELECT, parameters, limit, tests and stewards. Edit it here, then apply it.
Apply JSON
Replaces the draft with it; every check runs as on any other edit. Its name must stay the same; what is wrong is said in red beside the change.
