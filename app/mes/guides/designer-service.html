A service is a script the plant runs for you: called by an outside system as a web service, set off by a record's event, or by the clock. It reaches only what it names, acts as the identity you give it, and goes through review and approval like every other design. On a live design, or a change you may not edit, every control here is read only.

Its tabs

The tabs
General opens first. Click a tab to see its settings; the open one is highlighted.
A number on a tab
How many things on that tab differ from the live version. On Changes, the total.
Remove, and Undo
Every Remove asks first. What is removed leaves this change only; nothing live changes until the change executes, and Undo (⌘Z or Ctrl+Z) brings it back.

Copilot

The conversation
Ask the AI to draft, check or explain the service. It works as you, saves into this draft, and never submits. The conversation is kept with the change: it picks up here any time.
Ask the copilot…
Type what you want. ⌘ Enter or Ctrl+Enter sends; you can paste or drop a file into the box.
Attach
Adds a picture, a PDF, a CSV file or an Excel workbook (up to 5); × on a file takes it off.
Send
Saves your unsaved edits first, then sends. Greyed out while it works, or when no AI is set up.
New conversation
Asks first, then deletes the conversation kept with this change. The draft stays as it is.

Changes

The differences
What this change does to the service against the live version, grouped by tab: how many changed, were added and removed. Reviewers and approvers see the same.
Open …
Jumps to the tab where that group is edited.
A difference
Marked new, changed or removed; click it to open or close it. Lines marked − are the live version's, lines marked + the draft's.

General

Name
Fixed once created; its script is named after it (name.js).
Label
A text field: what people know it by.
Description
A text box: what it does, and for whom.
Web service
Tick it to let outside systems call it at POST /svc/v1/<name>, with an integration user's token (scope service:call). Only the callers named on Identity get an answer.
Deprecated
Shown for a web service. Tick it to warn its callers on every call that it will change or go: give them notice here first, change it after the sunset.
Since, Sunset
Dates: when the notice began, and the date after which it may change or go.
Successor
A text field: the web service its callers should move to, if there is one.
Note for its callers
A text box: what they should do, in your words. It is sent with the notice.

Input

The inputs
What a caller sends, one row each. Every input is checked against its type before the script runs; a bad one is refused with a message for that input.
Label
A text field: the input's name in words.
Type
A drop-down: string, text, integer, decimal, boolean, date, enum, ref or image.
Required
Tick it when a call without this input must be refused.
Values (enum)
For an enum only: the values allowed, as chips. Click into the box for suggestions, type and press Enter (or pick Add "…") for a new one; × or Backspace in the empty box removes one.
Remove
Takes the input out, after asking.
New input
Type its name (lower case letters, digits and _, starting with a letter), then press Add. Add stays greyed out until the name is valid.

Identity

Identity
A drop-down: who it acts as. Its own service role acts with exactly the roles below, whoever sets it off; its caller acts with the caller's own rights (not possible with triggers, which have no caller); Run as a person acts with their roles.
Service role
Shown for its own service role: tick the roles it holds on each object. Each object's policies decide what a role allows; that object's stewards approve the grant.
Users
Who may call it, as chips: click into the box and type a name to find a person, press Enter or click to add, × to remove. Nobody may call it until named.
Groups
Tick each group whose members may call it.

Triggers

On a record event
Each row sets it off after a record's change is committed (never for one rolled back), retried while the other system is down. A service never sets itself off.
Object
A drop-down: the kind of record. Changing it sets the event back to create.
Event
A drop-down: create, update, archive, restore, or transition: one of the object's actions.
Remove
Takes the trigger out, after asking.
Add trigger
Adds a row, on the first object's create.
On a schedule
Each card sets it off by the clock, once per time due however many nodes there are, in the plant's time zone unless the card names another. Pausing a live schedule is done from the integration monitor.
Its title
The schedule in words, kept up to date as you edit.
Runs
A drop-down: every…, at times of day, or a kind of schedule an installed suite adds. Changing it starts the new way afresh.
Every
A number and minutes or hours (1 to 720 minutes, 1 to 24 hours), counted from midnight.
At
Times of day as chips, typed HH:MM (6:00 is taken as 06:00): type one and press Enter; × or Backspace removes one. A time that is not one is refused, in words.
Only between
Two times: runs only in that window, which may cross midnight. Leave both empty for all day.
Days
Untick the days it should not run. All ticked is every day.
A suite's settings
For a kind of schedule a suite adds: the settings it asks for, those marked (needed) required. Its suite works the times out; while it is not installed, nothing is planned and the card says so.
Time zone
A text field, such as Europe/Paris. Empty: the plant's. Daylight saving is followed.
Missed runs
A drop-down: what to do with runs missed while every node or the database was down: run the latest one, skip them, or run each (up to 100).
While a run is still going
A drop-down: skip the new run, or queue it.
Next runs
Its next runs, in its time zone (the next five for a clock schedule). In red instead: what is wrong with the schedule.
Remove schedule
Takes the card out, after asking.
Add schedule
Adds a card, every 15 minutes. Add schedule: … adds one of a kind an installed suite adds, its settings empty.
Run on nodes tagged
Empty: any node runs its triggers and schedules. A tag (such as erp) keeps them to the nodes started with that tag, the ones that can reach the other system. Web calls run wherever they arrive.

Reaches

Connections
Tick each connection its script may send requests through. The connection's stewards approve it.
Transactions
Tick each transaction its script may run (ctx.transactions.run), all or nothing, through the transaction's own checks. One a person must sign is not offered.
From the … suite
Shown when an installed suite offers scripts something: tick only what this one asks of it. One whose suite is gone stays listed, so you can untick it.
Objects
Tick what it may do to each object's records: read, create, update, action, archive (and restore). Every write goes through the object's policies and rules; that object's stewards approve.

Script

The script
One function named as the service: context in, context out. Throw to refuse (the caller reads your words), or throw with { retry: true } when the other system is down. When it says the published script is not in this change, the live script stays as it is.
Its marks
A syntax error, a dry run's error, or what it may not call is marked on its line and said below; click the message to go there. Tab indents; Esc then Tab leaves the editor.
Compiles
Green when it compiles and its function has the service's name; otherwise the first problem, in red.

Dry run

Dry run
Runs this draft on the server, as its identity, exactly as it will live, and changes nothing: writes are checked and not saved, requests are checked and never sent. Click its title to fold it.
Dry run input
JSON: the input a caller would send (or the event of its first trigger), and responses, the answer each request gets, keyed by method and path.
Run
Runs it. An error in the script is reported first, by line.
Reset input
Puts the example input back.
as
Shown when it acts as its caller: a drop-down to run it as one of the users named on Identity.
The result
Ran, refused, asks to retry, or failed, as whom and how long. Below: its output, what it would write, run and send, and what it read.
Test case name
Say what this run shows, such as refuses an unknown work order.
Save as test case
Keeps the input and what happened as a test case. Greyed out until it has a name.

Test cases

Test cases
Run by the fitness test before the change can be submitted. A new or changed script needs at least one.
Its mark
A tick if it passed, a cross if it failed (the reason in red below), a circle if not run yet; faded when run before your latest edits. Point at it for the detail.
A case
Its name, who it runs as when not you, and whether it expects the service to run or to refuse.
remove
Takes the case out, after asking.
JSON, List
Shows the cases as JSON to edit their input or expectation by hand; List goes back.

Try it

Input as JSON
What to send the live version. A service not live yet cannot be tried: the tab says so until its change is executed.
Call it
Calls the live version as you, through its callers, its input checks and the policies and rules of what it touches. It is real, and audited: your draft is not what runs.
The answer
What a caller gets: the output in green, or the refusal in red.

Activity

Refresh
Fetches the latest calls and triggers again.
Calls
Each run of the live version: when, as whom, its outcome (with the error), how it was set off (web, schedule, trigger or the UI), what it sent or ran, and how long it took.
Triggers
The events and schedules waiting or done: their state, tries and last error.
Send again
Shown on one that is retrying, dead or refused: queues it again.

Stewards

Departments
Tick each department that approves every change to it. A change to what it reaches is also approved by the stewards of those objects, connections and transactions.

JSON

The service as JSON
All of it as data, for integrators. Edit it here, then apply it.
Apply JSON
Replaces the draft with it; every check runs as on any other edit. Its name must stay the same; what is wrong is said in red beside the change.
