A screen is a page made of blocks: a record, a table, a number, a chart, a transaction's form, a floor layout. Each block reads with the viewer's own rights, so a screen never shows what their forms would not. You design it here, inside a change; it reaches the plant only once the change is reviewed, approved and executed.

Its tabs

The tabs
The screen's settings, by topic. A number on a tab counts what differs there from the live version; a new screen counts everything.
The numbers
Differences from the published version on that tab. Changes lists them all, line by line.

Copilot

The copilot
An AI that drafts, checks and explains, working on the whole change as you. It never submits, reviews or approves. A live design shows no copilot: press Change it first.
Not set up
Shown when this installation has no AI configured: it says what is missing.
The conversation
What you asked, its answers, and each design tool it used (a tick when it worked, a cross when not). It is kept with the change: come back any time and it picks up there.
The box
Type what you want ("add a table of the lots on this machine"). Ctrl+Enter (⌘+Enter on a Mac) sends it. What you type is kept if you leave the tab.
Attach
Adds up to five files for it to read: pictures (a sketch of the screen), PDFs, CSV files or Excel workbooks. You can also paste or drop one into the box; × takes one off.
Send
Saves your unsaved edits first, so it works on what you see, then sends. What it saves shows in every window at once.
New conversation
Deletes the conversation kept with this change, after asking. The draft stays as it is.

Changes

The count
How many differences from the published version: changed, added, removed. A new screen says so; one that matches what is live says "Nothing differs".
By tab
Differences grouped by the tab where each is edited. Open … takes this window to that tab.
A difference
Click its line to fold or unfold it. Lines starting with + are the draft, lines with − the published version. A green edge is added, amber changed.

General

Name
Its fixed name, set when it was created. It opens at /s/ and this name.
Label
What the navigator and the screen's tab say.
Description
One line shown under the title.
Opened with
What the screen is about: nothing (the same for everyone), a record of an object (a machine's screen), a word (a line), or a date. The address carries it, and blocks read it as {"param": "name"}.
…called
The name blocks use for it: lower case, letters, digits and _. A name that does not fit is not taken.
…picked by
For a record: how the person picks it on opening, by scanning or typing its label, or from a list.
…only those where
Fields equal to these values, as JSON ({"process": ["die_saw"]}): a die saw's screen offers, and opens with, die saws only. Empty: any.
Fill the window
No: the usual page. On request: a Maximize button sets the navigator, top bar and tabs aside (a board on a wall, a tablet at a machine). Always at first: it opens maximized. Each device remembers the person's choice.
Input flow
How the screen is filled from a keyboard or scanner: its parameter, then its transactions' inputs, their tabs in turn, and back to the start. Pick one drawn in the Flow designer (kind input); none goes from input to input with Enter.
Open it
Shown once it is published: opens the live version, not your draft (see Preview for that).

Blocks

Blocks are drawn in this order on a row of 12 columns; a narrow screen stacks them.

A block
One card per block, numbered, with its kind. A green edge is new in this change, amber changed.
Earlier, Later
Move the block up or down the page.
remove
Takes the block out, after asking.
Title
Shown above the block.
Tab
The name of a tab of the screen to put it on; blocks with the same tab name share it. Empty: above the tabs.
Width
How many of the 12 columns it takes: 12 the whole row, 6 half, 4 a third.
Of
For a record, table, number, breakdown or floor: the object it reads. Changing it starts the block's settings afresh.
Shown when
A condition box over what the screen was opened with, its record, the person and counts. While it does not hold the block is not drawn, nor read. Empty: always.
Enabled when
While it does not hold the block is greyed and cannot be used; a tab whose blocks are all greyed is greyed too. Empty: always.
…because
Shown once there is an Enabled when: what the person reads on the greyed block and its tab ("This tool already has a lot on it.").
+ add a block
Pick a kind to add it at the end, with settings to start from. Suites may add kinds of their own. A screen holds at most 20 blocks.

One record

Which record
Usually the screen's own record, {"param": "machine"}; give the screen one to be opened with on General first.
Shows
Tick the fields to show, and its state.

A table of records

Only records where
Conditions, each field = value; with none, every record in use. Also on numbers and breakdowns.
+ condition
Pick the field (or state) to filter on. A reference to the screen's own kind of record starts as the screen's parameter.
Its value
JSON on one line: "value", a list such as ["processing"] (any of them), or {"param": "machine"}. Outlined red until it reads.
×
Removes that condition.
Columns
Tick the columns to show. The first links to the record.
Sorted by
A column to sort on, or last changed first.
Direction
Ascending or descending, once sorted by a column.
At most
Rows in all, 1 to 1000.
Drawn at a time
Rows drawn at first, 5 to 200; more come as it is scrolled.
Record buttons
New for whoever may create one; Remove on each row (it archives the record) for whoever may archive it. Through the object's own policies and rules.
Buttons on each row
Tick transactions that appear on these records: each runs right there, the row filled in, on rows in its states.
…filling in
When the screen is opened with a record: inputs of those transactions the screen's record can fill, shown locked on the row's form (the screen's machine on Move in), or left to the person.

A number, and a breakdown (bars)

By
A breakdown only: what the bars are, its state or a field with few values.
Measure
How many records, or the sum, average, least or most of a number field.
Changed
Only records last changed today, in the last 7 or 30 days, or at any time.
Says
A number only: the word after it (lots).

A chart from a query

Chart
The kind: bar, line, area, scatter, bubble, pie, donut, funnel, heat map, box plot, histogram, radar, gauge, tree map, sunburst, sankey, waterfall, Pareto, candlestick, or bars and lines. Under it, what the kind is for. Changing it keeps the query.
Query
Written as JSON (it may name the screen's parameter) or as SQL. Switching starts the query afresh.
JSON query
As on the Queries page: from, select, groupBy, where, in which {"param": "…"} stands for the screen's parameter. Run as whoever opens the screen.
SELECT
One SELECT over the views of the Queries page, run as whoever opens the screen. Name its columns (AS lots) and use those names below.
Its columns
Which query column goes where, by name; * marks those the kind needs. x along the bottom; series a column whose values each become a series; size a bubble's size; value the amount of a cell, part or flow; source and target a sankey's ends; open, close, low, high a candle.
Column lists
Tag lists of columns: y the values drawn, path a tree map's or sunburst's levels (top first), lines a combo's columns drawn as lines.
unit
A word after each value: h, %, pcs.
Drawn
Tick what applies to this kind: stacked, bars across, smooth or stepped lines, each value written, a logarithmic axis.
Reference lines
Lines across the chart, as JSON: [{"value": 95, "label": "target", "tone": "ok"}]; a target, control limits. Tones: neutral, info, ok, warn, danger.
Bands
Shaded ranges, as JSON: [{"from": 0, "to": 60, "tone": "danger"}]; a gauge's coloured arcs.

The value axis's least and most, and a histogram's number of bins, are set on the JSON tab (min, max, bins).

A transaction's form

Transaction
The transaction whose form the block shows. Changing it clears what the screen fills in.
Filled in by the screen
For each input: entered by the person, or the screen's parameter where it fits, shown locked.
In a dialog
Ticked, the dialog closes once the transaction is done, when this screen was opened as a dialog (by a button or a pop-up).

Text

Text
Words for the people at the screen, an instruction or a note: a line per paragraph, - for a list, **bold**, # a heading, [words](https://…) or [words](/s/screen) for a link.

A file: a guide, a picture, a video or a PDF

Shows
A file of its own, uploaded here: the station's guide, a drawing, a video of the job (a picture up to 5 MB, a PDF 10 MB, a video, MP4 or WebM, 100 MB). Or a record's file or picture: Of an object, Which record (the screen's: {"param": "lot"}) and the Field; a field derived through a reference shows that record's, so a station opened with a lot shows its step's instruction. A record's file is read as whoever opens the screen.
Steps
A line each: the page (a PDF) or the time (a video, 0:45) the step starts at, then its words. Written here for its own file; for a record's, Steps from a text field of that record. At the screen they give big Previous and Next buttons, the step being shown, and the steps to jump to; a video's step stops at its end unless that box is unticked. A line may end with how the step is done: #click (the default), #value:<input>, #photo, #file, #device, #wait or #screen:<name>.
Steps marked done by
A transaction that records a step done, one record per step: the input taking the step's number, where photos and files go, what the screen fills in, and the records that say a step is done (Done when there is a, whose step is, and where). Each mark is that transaction's run, with its checks and the audit trail; a record the equipment writes ticks its step at once. Tick Next only once the step in view is done to hold the operator on each step. A step done can be undone by whoever may archive its record; a transaction a second person verifies asks for them beside the operator, as on its form.
Follows a route
The steps are the route's sequences placed in this guide (In the guide at, in the Flow designer), for the lot in Whose way: it opens where the lot is and ticks each step it has left.
Height
For a PDF, read in the page, or a video, played there: in pixels.

A button that opens a screen

Opens
Another screen, opened as a dialog over this one.
Label
The button's words; left unset, it says the other screen's label.
Opened with
The value it opens the other screen with, if that one takes one, as JSON: {"param": "machine"}.

A floor layout

Status
What each record's small square shows: its state, or a field. It follows the record as it changes.
Each record's picture
An image field of the record, or of what it refers to (its model: one picture for every tool of the model). None: a plain tile with its name.
Legend
A colour for each value of the status, or its tone, or grey. Colours are the theme's, so they read in light and dark.
Upload the floor's picture
A top view of the floor or the line: PNG, JPEG or WebP, at most 5 MB. Replace it the same way.
Find records to place
Type part of a name, then click a record (or press Enter) to put it on the floor; up to 200.
The floor
Drag a record to where it stands, and its small square to where it sits on it (its signal tower, its screen). Click one to choose it; the arrow keys move it a step, with Shift a larger one.
Size
How wide the chosen record is drawn.
Same size and square for its like
Draws every record with the same picture as wide, its square at the same spot.
Take it off the floor
Removes the chosen record from the floor.

A suite's block

Its settings
A block an installed suite adds: its settings by name, (needed) where one must be given. If its suite is not installed it says so; the screen's other blocks still work.

Preview

What it is opened with
For a screen opened with something: pick the record, or type the value, to draw it with.
Redraw with the draft
Draws the draft again with your latest edits.
Problems
What stops the draft from drawing, in red.
The screen
The draft as it will look, read with your own rights on each object. Its buttons do nothing here.

Pop-up

Opens by itself
Ticked, this screen opens as a dialog over the pages you choose while its condition holds, and closes when it no longer does. It only shows: what must not happen is refused by the transaction's own checks.
Over
Tick the pages: every page, a transaction's screen, or another screen.
For: groups
Tick the groups it opens for.
For: people
People named one by one: type part of a name and pick from the suggestions.
While
A condition box over the page: a transaction's inputs ({"lookup": "machine.state"}), a screen's parameter, the person and counts. None: it never opens by itself.
Opened with
Its parameter, if it has one, taken from the page: {"input": "machine"}.

Callers

Groups
Tick the groups whose members may open it. Nobody may until named here.
Users
People named one by one: type part of a name and pick from the suggestions; × on a name removes it.

What each sees in it is still their own rights on each object.

Stewards

Departments
Tick the departments that approve every change to it. A screen writes nothing itself: a transaction it shows is approved as a transaction.

JSON

The whole screen
All of it as JSON, for integrators. Edit it here; nothing changes until you apply.
Apply JSON
Replaces the draft with it, checked like any other edit. Refused if it does not read, or if the name changes.

Everywhere in it

Condition boxes
A rule in words. Click it, or Edit (Add a condition while empty), to build it from rows: a field, an operator, a value, in groups (all of, any of, none of), or from a pattern. JSON shows the same as text; Try lets you type values and see whether it holds. Empty means what its box says (always, never).
A condition's problem
Said in red under the box: what does not read, or names something unknown.
Tag lists
Chosen values as chips; × removes one. Click into the box for suggestions, Enter or a click adds one, Add "…" adds a new value, Backspace in the empty box removes the last. Lists of people take only people who exist.
JSON on one line
A value or expression as JSON, outlined red until it reads; applied as soon as it does.
Diff marks
Green: added in this change. Amber: changed. What was removed is listed on Changes.
Remove, and Undo
Remove always asks first; nothing live changes until the change executes. Undo (⌘+Z or Ctrl+Z, outside a text box) brings it back.
